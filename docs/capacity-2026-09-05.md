# Capacity / ops (2026-09-05)

Schema **2** adds rough capacity planning on top of the existing lab notebook. Not live monitoring — guesses you type in.

## Data model

**Inventory item** (Stuff I have) now accepts optional:

- `role` — `pc` | `nas` | `pi` | `switch` | `ap` | `other`, or short free text
- `cpu` — cores (number)
- `ramGb`, `storageGb`, `watts`
- `needsAttention`, `attentionNote`

**Services** array (new):

- `{ id, name, hostId?, ramMb?, cpuPct?, notes?, url? }`
- `hostId` links to an inventory `id`
- Cap 100 services (same as other arrays)

**Lab-level** (optional UPS sketch):

- `upsVa` — number
- `powerNote` — string

Stored in D1 as `services_json` + `capacity_json` (migration `0004_capacity.sql`).

## Export / import

- Export writes `schema_version: 2`
- Import accepts `1` or `2` (or omitted = legacy v1)
- v1 inventory migrates through sanitizers (new fields stay absent until filled)

## UI

- **Stuff I have** — expandable specs; attention toggle
- **Services** — list, host picker, RAM/CPU %, preset chips (Pi-hole / Immich / Samba / … labeled as rough guesses)
- **Headroom** — per-host RAM used/avail bars, CPU share sum, house watts vs UPS VA if set

Existing panes, auth, enroll, PWA, tour, and passkey nudge stay as they were.

## Worker

`sanitizeInventoryItem`, `sanitizeService`, `sanitizeCapacity`; `emptyLab` / `clampLab` / `getLab` / PUT / import include `services` + capacity fields.
